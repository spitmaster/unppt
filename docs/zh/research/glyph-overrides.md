# 符号的显示字体替代表（2026-10-28）

> 结论：默认字体包里，少数符号的开源字体画法和微软字体差得太多（例如 `√`），对这些符号单独换一个画法接近的开源字体显示。
> 表由脚本自动生成：[`packages/transcoder/src/font/glyph-overrides.ts`](../../../packages/transcoder/src/font/glyph-overrides.ts)。

## 为什么需要

默认字体包不用观看者电脑上的字体：微软雅黑、等线、黑体这类中文字体，按原字体的字宽排版，显示时用开源的思源黑体（宋体类用思源宋体），
所有观看者看到的一样（SPEC D3）。汉字两边设计很接近，看不出区别；但**少数符号两边的画法完全不同**。最典型的是 `√`（U+221A）：

- 微软雅黑里画成一个**对勾**，很多课件拿它当"打勾"用；
- 思源黑体里画成标准的**数学根号**，右上角带一条长横线，宽一整个字。

所以课件里的"打勾"在 unppt 里变成了"开根号"。同类的还有雅黑的 `…`（雅黑在基线上、思源在中间）、`≤ ≥`、`○ ● □`，等线的中文引号等。

## 怎么找出来、怎么选

脚本 [`tools/fonts/glyph_audit.py`](../../../tools/fonts/glyph_audit.py)：

1. 统计本机全部课件里实际用到的非汉字字符和出现次数（只记字符和次数，不出本机）；
2. 对常用的中文字体（雅黑常规 / 粗 / 细、等线、黑体、宋体），把每个出现 50 次以上的字符分别用原字体（Windows 自带的）和
   开源字体画出来，按排版时的位置摆放（字宽框居中、基线对齐），轻微模糊后算**形状相关度**（0~1，1 = 一样；模糊是为了容忍几个像素的
   差别，只有整体画法不同才会明显变低）；
3. 现在用的开源字体相关度低的，在字体包里**同类风格**的开源字体中挑最像的：黑体类只在思源黑体、Liberation Sans、Carlito 里挑，
   宋体类只在思源宋体、Liberation Serif、Caladea 里挑（仿宋、楷体的标点放进黑体句子里风格突兀，不用）；
4. 只有差别明显才换：现在的相关度 < 0.6、换上的 ≥ 0.85、而且至少提高 0.3。第一次跑出 38 项（雅黑的 `√ … ≤ ≥ □ ○ ●`、等线的引号和 `· ² ³`、
   黑体的 `√` 等）；逗号、句号这类常用中文标点没有找到明显更好的同风格字体，不换。

## 转码时怎么用

只在**默认字体包模式**、而且这个字本来就是用替代的开源字体显示时才查表（`text/measure.ts`）：命中就换成表里的开源字体画这个字。
**字宽和排版不变**（仍按原字体的字宽排），只换字形，字形在原字体的格子里居中。用 `--system-fonts` 或课件嵌入了字体时用的就是真字体，不查表。

效果（一份含 `√` 打勾、带 `“”` 引号的课件，42 页，默认字体包模式和 PowerPoint 导出的图比）：打勾那页相似度 0.925 → 0.930，全份平均 0.9171 → 0.9179，没有页变差。

## 维护

- 字体包换了开源字体、或者要覆盖新的中文字体时，重新跑：`python tools/fonts/glyph_audit.py`（第一次统计字符要几分钟，之后用缓存），
  它会重写 `glyph-overrides.ts`（生成的文件，别手改），提交前跑合成用例和全量比对。
- 阈值和候选字体在脚本开头（`BAD`、`GOOD`、`GAIN`、`SANS`、`SERIF`），改了要在提交信息里说明原因。
- 如果某个符号在字体包所有同风格字体里都找不到像的（相关度都低），就只能往字体包里补字形，那需要发新版字体包。
