# 优化路线图：围绕五条产品要求的实测调研（2026-10-26）

> 来源：用脚本和浏览器实测得到的数据，只覆盖其中两个方向（**播放一致性与屏幕适配**、**动画 / 切换 / 媒体**）。
> 另外四个方向（转码速度、播放性能、排版与字体无关、测试盲区）当时被额度打断，**还没做**，见 [交接文档](../../todo/handoff.md)。
> 数字都来自当时的实测；工作量、运行时间凡标"估计"的没有实测。只有汇总数字，不含任何单份课件的信息。

五条要求：R1 转码快 · R2 播放一致、适配各种屏幕 · R3 播放性能 · R4 排版一致（字体可以不同） · R5 动画和媒资一致

---

## 一、按"影响 ÷ 工作量"排序的事项


### 1. 舞台位移取整到设备像素
- **问题**：`Player.fit()` 的 `translate(x,y)` 没有取整。Chromium 截图里 41%（520/1,276）的舞台落在半像素上。
  - Chromium 在小数位置抗锯齿，幻灯片边缘出现灰缝（这一行的均值 132~183/255）；Firefox 吸附到整像素。
  - 两个内核因此整页错开 1 个设备像素：375x812@1 下 116 对里有 100 对，@3 下 116 对全部。跨内核 SSIM 0.863，对齐后 0.981。
  - 只挪 0.5px 时，细线页的清晰度最低降到 0.80。
- **影响**：R2
- **做法**：
  - `x = Math.round(x*dpr)/dpr`，y 同理。
  - 用 `matchMedia('(resolution: …dppx)')` 监听像素比变化（拖到另一块屏、浏览器缩放），变化时重新适配。
  - 1:1 截图不变，golden 不受影响。
  - 实测收益：375x812@3 尺寸一致性 0.969 → 0.988，@1 0.927 → 0.962；16:9 课件清晰度回到 1.000。
- **工作量**：小（估计半天内）
- **自动验收**：
  - check-player 在 375x812@3、1280x721、1000x300、812x375@1 下读 `.unppt-stage` 的 transform，`e·dpr`、`f·dpr` 必须是整数。
  - 跨内核整屏截图做 ±1px 对齐搜索，最佳偏移必须是 (0,0)。

### 2. 所有字形都来自嵌入字体：空格进子集，font-family 去掉原字体名
- **问题**：
  - `text/measure.ts` 的 `cp > 0x20` 和 `chart-fonts.ts` 的 `cp <= 0x20 continue` 把空格排除在子集外。49 份产物里缺的字只有空格一种，共 991 个（2.4%）。
  - 字体全部加载完后，15 份真实课件里仍有 13 份有字形由观看者本机字体画。
  - 图表文字是单个 x 加 `text-anchor`。后备字体为 SimSun 时，59 个带空格的图表文字全部移位，最多 3.6 幻灯片像素。全量课件里最多 4.4%（216/4,887）涉及。
  - font-family 里写了原字体名（如微软雅黑）。没覆盖到的字，在 Windows 观看者上会用微软字体，在手机上用系统字体。
- **影响**：R4、R2
- **做法**：
  - 两处判断改成 `cp >= 0x20`，并把 U+00A0、U+3000 等空白字符放进子集。
  - font-family 只留嵌入别名和通用族名。
  - 这会改变产物（每个字体多几十字节）。按规则 5、8：用 golden 确认只有这一处变化，再做全量 A/B，并在提交信息和 docs/todo 里写明原因。
- **工作量**：小（改代码估计半天；全量 A/B 的机器时间另算）
- **自动验收**：
  - 合成用例加日常集，等 `fonts.ready` 后用 CDP `getPlatformFontsForNode` 统计 `isCustomFont=false` 的字形数。除已声明没嵌入的符号字体外，必须为 0。
  - 把后备字体换成 SimSun、Arial，单个 x 的文字外框位移必须 ≤ 0.1px。

### 3. 放不了的媒体要能被发现、被提示
- **问题**：418 份带媒体的课件里，56 份（13.4%）至少有一个媒体在 Chrome 154、Edge、Playwright Chromium、Firefox 里都放不了。
  - 内嵌 34 处（21 份）：AVI 18、ASF/WMV 4、WMA 6，另有 6 个 MP4 装的是 MPEG-4 Part 2。最后这种只有声音，画面停在封面上，而且不报错。
  - 外链 60 处（37 份）：file:// 55 处，http 5 处。
  - 转码器原样复制、不报警；播放器吞掉 `play()` 的失败，封面一直在，点了才发现。
- **影响**：R5
- **做法**：
  - ① 转码器嗅探容器和编码（RIFF AVI、ASF 头 GUID、MPEG-PS、MP4 `stsd` 的 fourcc、音频条目）。放不了的和外链的写进 `report.warnings` 和 `unppt check --json`，带页号和原因。
  - ② 播放器在 `error` 事件、或 MP4 开始播放后 `videoWidth=0` 时，显示“格式不支持”，并发桥接事件。
  - ③ 可选，需要产品决定：增加 `transcodeMedia` 钩子，云端接 ffmpeg 转成 H.264/AAC，`convert()` 仍然是纯函数。
- **工作量**：①② 小到中；③ 中
- **自动验收**：
  - 全量跑 `unppt check --json`，统计报出的不可播数量（当前预期：内嵌 34 + 外链 60）。
  - 中性夹具（AVI、WMV、mp4v-in-MP4、WMA、外链）里任何一个没被报出，就判失败。

### 4. 修一处顺序 bug：visibility 时长为 indefinite 时退回旧绘制
- **问题**：`compileBehaviors` 先调用 `timingOf(tn)`，后跳过 `style.visibility`。visibility 的 set 写了 `dur="indefinite"` 时，整条效果会退回旧的按预设绘制。
  - 涉及 843 个效果、54 份课件：Fly 245、Wipe 170、Dissolve 147、Zoom 144 等。
  - 旧的 fly 绘制和 PowerPoint 的误差是 0.077，走行为解释器是 0.010。
  - 另有 458 个效果（58 份）的 animEffect 没有 filter，也会退回；PowerPoint 实际怎么播还不知道。
- **影响**：R5
- **做法**：
  - 把 visibility 的判断挪到 `timingOf` 之前。
  - 空 filter 的情况，先用一个 COM 中性用例探 PowerPoint 的表现，再决定怎么处理。
- **工作量**：小
- **自动验收**：
  - 全量扫描计数 `behfail.*.bad-timing` 必须为 0（今天是 843）。
  - 单元测试：visibility set 的时长为 indefinite 时，仍然产出 behaviors。

### 5. 默认的 paged 形式：等这一页的字体到齐再显示
- **问题**：`show()` 只等页面数据。字体脚本没到之前，浏览器直接用观看者的系统字体画。
  - 3G（1.6Mbps，RTT 150ms）下：首页在 0.72~1.74s 出现，字体到齐要 0.97~3.98s，空窗中位 0.95s、最长 2.74s。
  - 10/15 份课件首屏有系统字体字形，最多 133 个。首屏和最终画面的 SSIM 最低 0.65（其中也有图片还没加载的因素）。
  - 4G 下空窗中位 0.24s。single 形式没有这个问题。
  - 直播课里学生中途进入、观看端 sync 跳页时都会看到。
- **影响**：R2、R4（首屏排版会跳）、R3（感知速度）
- **做法**：
  - 每页数据或目录带上这一页用到的字体别名（要加产物字段）。
  - `show()` 前等 `document.fonts.load` 和对应的字体脚本，上限 2~3s，期间沿用现有的“加载中”提示。
  - 预加载下一页时，同时预加载它的字体。
  - 可选：当前页图片也等 decode 完再显示。
- **工作量**：中
- **自动验收**：check-paged 用 CDP 把网络限到 3G，在第一个 `.unppt-slide` 插入时统计 `isCustomFont=false` 的字形数，必须为 0。“页面出现 → 字体齐”的空窗作为跟踪值。

### 6. 补齐行为解释器：强调、路径也走同一套行为
- **问题**：1,291 个效果、143 份课件动得不对或不动：
  - 入场里带 animMotion 的 360 个（55 份），退成淡入。
  - 用 ppt_x/ppt_y 写的路径 351 个（11 份），编译出的目标为空，完全不动。
  - 闪烁 235 个（21 份），被忽略。
  - 彩色打字机 196 个（32 份），退成淡入。
  - 逐字波浪 71 个（25 份），丢了位移部分。
  - xshear 33 个（12 份），退成淡入。
  - hsl 相对颜色变化 31 个、线条颜色变化 14 个，被忽略。
- **影响**：R5
- **做法**：
  - 强调和路径效果改走入场 / 退出已经在用的行为解释器。
  - 新增行为类型：animMotion、离散的 visibility、颜色（`clr` / `animClr by hsl`）、`stroke.color`、xshear/yshear（用 CSS skew）。
  - goto 的最终状态用同一套行为在结束时刻采样，保证跳转和播放的结果一致。
  - 每种新类型用 capture-anim 和中性用例校准。
- **工作量**：中
- **自动验收**：
  - 编译后带 behaviors（或目标非空）的效果占比：今天 97.2%，目标 ≥ 99%，下降就判失败。
  - 这些预设编译出的强调 / 路径效果里，目标为空的数量为 0。

### 7. 切换效果的三件小事
- **问题**：32,883 张有切换效果的页面里：
  - 13.2%（4,351 张，390 份）退成淡入。最多的是 random，2,562 张（177 份）。
  - 时长被 `Math.min(3000, dur)` 截断，157 张（99 份）放得比原来快。
  - 1,268 张（约 60 份）自己没有切换、但版式或母版有（其中 650 张有效果），PowerPoint 是否继承还没验证。
  - 另有 7.9% 用平面效果代替 3D。
- **影响**：R5
- **做法**：
  - ① 去掉 3 秒上限，改成约 60 秒封顶。
  - ② 用一次 COM 探针确认是否继承；如果继承，按“幻灯片 → 版式 → 母版”依次回落。
  - ③ random 保持确定性（所有观看者一致优先），按页序号哈希，从已实现的类型里挑。
  - ④ 卷页、剥离等以后再做，做之前先用 transitions.py 量。
- **工作量**：小（①③）；② 是一次探针
- **自动验收**：
  - 播放器单测：5 秒切换的 Animation 时长等于 5000。
  - 扫描计数：被截断的时长为 0；退成淡入的占比 ≤ 13.2%，只降不升。

### 8. SMIL fill 语义：每步结束后的状态不对
- **问题**：
  - Flash Once 232 个（6 份）：只有一个 dur=100、不保持的 visibility set，现在变成常驻的淡入。按 SMIL 语义应该再隐藏（推测，还没探）。
  - 播完倒回（`fill=remove`）55 个（20 份），没有处理。
  - 字符范围 charRg 491 个（38 份），整个形状一起动。
  - 按元素 `iterate el` 580 个（43 份），按整体播；是否正确待确认。
- **影响**：R5
- **做法**：
  - 每个行为按 SMIL fill 处理：不保持的 set 到点恢复；`fill=remove` 时，播放和 goto 都回到效果之前的状态。
  - charRg 像 pRg 一样映射到子 run 的 uid。
  - Flash Once 和倒回各用一个中性 COM 探针确认，规则写进 SPEC 第 7 节，再加进 anim-* 用例。
- **工作量**：小
- **自动验收**：COM 审计从“步数”扩展到“每步结束时谁可见”：PowerPoint 执行 Next() 后的 Shape.Visible，对比播放器的 `.unppt-hide` 集合。固定一组课件，不一致数只降不升。

### 9. 页面底色画进 SVG（防强制深色模式）
- **问题**：Chromium 强制深色模式下，6 页里有 1 页 SSIM 只有 0.59。这一页的背景图半透明，透出的 `.unppt-stage` CSS 白底被变暗了。
  - 各种 `color-scheme` 声明都退不出（仍是 0.5894）。
  - 在 SVG 里垫一块白色矩形、舞台背景设成透明后，升到 0.919；剩下的差别在一个渐变标题条。
- **影响**：R2
- **做法**：根 SVG 第一个子元素放全尺寸白色矩形，舞台不再依赖 CSS 白底；`color-scheme` 声明顺手加上。改的是产物，要走 golden。
- **工作量**：小
- **自动验收**：用 `--blink-settings=forceDarkModeEnabled=true` 渲染全部合成用例，和正常模式比每页的 SSIM。报告建议 ≥ 0.99；那一页修完实测 0.919，阈值先按实测值设，只升不降。

### 10. 缩小显示时细线变淡（和 PowerPoint 规则相反）
- **问题**：
  - 真实课件里 73%（869/1,188）的描边 ≤ 1 幻灯片像素。
  - 同一个边框的对比度：1:1 时 55 级，1024x768 降到 31，640x360 降到 20，375x812@1 降到 13。
  - 800x450 的嵌入框里，74% 的描边窄于 0.75 设备像素。
  - PowerPoint 实测规则：不到 1 像素的线画成 1 个设备像素，颜色不变淡。
  - 现有的 SSIM 指标发现不了这个问题。
- **影响**：R2、R4
- **做法**：
  - `fit()` 里设 `--unppt-px = 1/(s·dpr)`，即 1 个设备像素等于多少幻灯片像素。
  - 转码器对取整前 ≤ 1px 的实线输出 `stroke-width:max(<w>px,var(--unppt-px,0px))`。
  - 整页图（resvg）不认 CSS 变量，照旧画原线宽，不受影响。
- **工作量**：中
- **自动验收**：
  - lines-thin-dash 和带边框的表格，在 640x360@1、800x450@1、375x812@2 下，最暗列的对比度 ≥ 1:1 时的 90%。
  - DOM 统计“线宽 × s × dpr < 1 且没有用 max() 的描边”占比为 0。

### 11. MP4 改成 faststart（moov 放到 mdat 前面）
- **问题**：436 个 MP4/MOV/M4A 里 228 个（52%，2.62GB）的 moov 在 mdat 后面，其中 45 个大于 10MB、4 个大于 100MB。
  - 服务器支持 Range 时，浏览器要先取文件尾才能开始播。
  - 不支持 Range 的服务器或 CDN 要整个下载完。
- **影响**：R3（首帧时间）；R1（要量额外的 CPU）
- **做法**：
  - 复制时用纯 JS 重排成 ftyp → moov（平移 stco/co64 偏移）→ mdat，不解码。
  - 媒体 zip 条目 63% 是不压缩存储的，可以一次处理完；压缩存储的条目要先扫一遍找 moov，这部分 CPU 开销要量。
  - 按输出内容重新算哈希命名。
- **工作量**：中
- **自动验收**：
  - 输出 MP4 中 moov 在 mdat 前的占比为 100%。
  - 在限速的本地服务器上用 Playwright 测首帧时间，不比输入差。
  - 转码耗时的增加量要记录（这个还没测）。

### 12. EMF/WMF 图片里的文字用了观看者的字体
- **问题**：EMF 转成的 SVG 用 `<image>` 引用，用不到页面注册的字体。
  - 全量 4,887 份课件里，638 份（13%，上限）有带文字的 EMF/WMF。
  - 8,373 个 EMF/WMF 文件里有 1,911 个带文字。
  - SPEC D3 ⑨ 已经把它列为没做的部分。
- **影响**：R4、R2
- **做法**：
  - 先在 `report.warnings` 里统计数量（小）。
  - 再二选一：(a) 有文字的 EMF SVG 直接内联进页面 SVG（放进 `<g>`，加 clipPath），选字体走逐字流程；(b) 每个 EMF SVG 自带 data URL 形式的子集 @font-face。
- **工作量**：大
- **自动验收**：转码时统计“没有可用嵌入字体的 `<text>`”数量，写进 report，门禁目标为 0。

## 三、先建的自动门禁（以后靠它把关，少靠人工和 LLM 看）

原则：阈值从今天的实测值起步，只能收紧；改阈值或基线要在提交信息和 docs/todo 里写明原因（规则 5）。下面的运行时间都是估计。

| 顺序 | 门禁 | 检查什么 | 何时跑 | 运行时间（估计） |
|---|---|---|---|---|
| G1 | **产物静态清单**（不开浏览器） | 动画编译覆盖率 ≥ 97.2% 只升不降，`bad-timing` = 0，强调 / 路径目标为空 = 0；切换的退化计数；媒体可播性报告覆盖全部中性夹具；子集包含空格；EMF 里没有嵌入字体的 `<text>` 数 | 合成用例进 `npm test`；全量课件扫描放到发版前 | 合成用例几秒；全量 5,212 份没计时，用最低优先级、限并发跑 |

| G3 | **媒体行为** | 不可播夹具被报出；播放器显示错误提示；静音视频 `muted===true`；自动播放被拦截时发事件、点击后恢复 | check-player / check-live | 数十秒到数分钟 |

## 二、各方向的实测发现（原始记录）

### 播放一致性与屏幕适配：不同观看者看到的是否一样、各种尺寸 / 设备像素比 / 浏览器内核下是否一致

**现状**：实现方式（读 packages/player/src 得出）：每页是一张按幻灯片像素画的 SVG（如 viewBox 1280x720），放在同尺寸的 .unppt-stage 里，由 Player.fit()（core/player.ts 第 260-266 行）用 CSS `translate(x,y) scale(s)` 等比缩放并居中，x、y 不取整。ResizeObserver 和 window resize 时重新适配，iframe 缩放和"先隐藏后显示"在 Chromium、Firefox 里实测都正确（误差 ≤0.008px）。播放器没有任何按设备像素比的处理，没有全屏 API，转屏只靠 resize。正文按字逐个给 x 坐标；图表文字是单个 x 加 text-anchor，再加 dominant-baseline=central。font-family 写成 `'unppt-fN','原字体名',sans-serif`，原字体名就是 Microsoft YaHei、等线这类。single 形式一开始就注册全部 FontFace。paged 形式（默认）每个字体是一个脚本，一开始就加载，但显示页面不等字体。index.html 的 viewport 设了 `maximum-scale=1,user-scalable=no`。
测量方法：在本机 scratch 里用当前 dist 转了 15 份真实课件（16:9、4:3、9:16 竖版、1.45、1.87，带视频、带 EMF）和 34 个合成用例，49 份全部转码成功，共 357 页。截图用 Playwright 的 chromium-1243、firefox-1543；**WebKit 没装**，iOS WKWebView 没测到。Chromium 跑 11 种视口/像素比组合，Firefox 跑 4 种，共 1276 张 Chromium 截图。
主要数字：
- 尺寸一致性：拿 2560 宽截图按面积平均缩小后和原生小尺寸截图比 SSIM（8x8 分块）。桌面尺寸（116 页）：1024x768 0.985，1280x720 0.990，1920x1080 0.990，640x360 0.978。手机竖屏（80 页，整屏截图后按设备像素裁剪）：375x812@1 0.927，@3 0.969。
- 跨内核（Chromium 对 Firefox）：1280 均值 0.990，中位 0.998，允许错开 1 像素对齐后 0.994；1920 0.994。375x812@1 只有 0.863，116 对里 100 对两边整体差 1 个设备像素，对齐后 0.981。
- 观看者设置：最小字号 8/12、文字自动放大、无障碍字号 1.5 倍、强制高对比色，对 SVG 文字都没有可见影响。
- 现有评测（compare/run.py、sweep_ab.py）只在 Chromium、1:1 尺寸、等 fonts.ready 之后截图；check-player 在手机上只检查宽度。所以下面这些问题现在都测不到。

- **舞台位移不取整：41% 的视口下整页落在半像素上，Chrome 发虚、Firefox 取整，两个内核差 1 像素**（影响 high，工作量 small）
  - 证据：Player.fit() 写的是 translate(${x}px,${y}px)，x = (W - w·s)/2 不取整。1276 张 Chromium 截图里有 520 张（41%）舞台位移不是整设备像素，例如 375x812 时 y=300.53，9:16 课件在 1280x720 时 x=437.5。不裁剪的整屏截图证实这是渲染本身的差别：Chromium 在小数位置抗锯齿，幻灯片边缘一行变成灰缝（行均值 132~183/255）；Firefox 吸附到整像素（边缘 255）。结果是两个内核整页错开 1 个设备像素：375x812@1 下 116 对里 100 对、@3 下 116/116 对要挪 1px 才对得上，跨内核 SSIM 从 0.863 升到 0.981。清晰度：同样是 1:1 缩放、只挪 0.5px（视口 1280x721 或 1281x720，12 份课件 22 页），边缘能量均值降到 0.959 / 0.976，细线页最低 0.80；在页面里把位移取整到设备像素后，16:9 课件全部回到 1.000。尺寸一致性：375x812@3 的 SSIM 0.969 → 0.988（半分辨率 0.980 → 0.992），375x812@1 0.927 → 0.962（80 页）。
  - 建议：fit() 里把位移取整到设备像素：`x = Math.round(x*dpr)/dpr`，y 同理。另外用 matchMedia(`(resolution: ${dpr}dppx)`) 监听像素比变化（拖到另一块屏、浏览器缩放），变化时重新适配。改完 1:1 的截图不变（位移原本就是 0），scripts/golden.mjs 不受影响。
  - 自动验收：check-player 加单元断言：在 375x812@3、1280x721、1000x300、812x375@1 下读 .unppt-stage 的 transform，e·dpr 和 f·dpr 都必须是整数。再加一道跨内核检查：同一页 Chromium 和 Firefox 整屏截图做 ±1px 对齐搜索，最佳偏移必须是 (0,0)。现成脚本：scratch 里的 probe_subpixel.py、fixcheck.py、fullshot.py。

- **空格不进字体子集，正文以外的空格要用观看者自己的字体；图表标签位置随观看者变**（影响 high，工作量 small）
  - 证据：text/measure.ts:219 写的是 `cp > 0x20` 才进子集，render/frames/chart-fonts.ts 里是 `if (cp <= 0x20) continue`，所以所有子集都没有 U+0020。49 份产物共 41,738 个字，缺字只有空格一种，共 991 个（2.4%）。用 CDP CSS.getPlatformFontsForNode 查实际用的字体：字体全部加载完以后，15 份真实课件里仍有 13 份有字形是本机系统字体画的（Microsoft YaHei、DengXian、Yu Gothic、SimHei、FZYaoTi）；合成用例里也有 Calibri、Arial、Times New Roman、Cambria 等。逐字定位的正文看不出来；但图表文字是单个 x 加 text-anchor，空格宽度来自后备字体。模拟观看者后备字体是 SimSun（Mac/手机上也会是别的字体）：59 个带空格的图表文字全部移位，最多 3.6 幻灯片像素，start 锚点平均 3.6，middle 平均 2.1；换成 Arial 或 Segoe UI 时位移 ≤0.1。全量 4887 份课件里有图表的 713 份，图表字符串含空格的 216 份（4.4%，是上限）。另外 font-family 写了原字体名（如 'Microsoft YaHei'），任何没覆盖的字在 Windows 观看者上会用微软字体，在手机上用系统字体。
  - 建议：子集包含 U+0020（以及 U+00A0、U+3000 等空白字符）：两处判断改成 `cp >= 0x20`。font-family 列表去掉原字体名，只留嵌入别名和通用族名，这样漏网的字至少不会挑中观看者装的微软字体。这会改变产物（字体多几十字节），要按规则 5、8 写明原因，并用 golden 和全量 A/B 确认只有这一处变化。
  - 自动验收：门禁脚本（scratch 里的 probe_fonts.py）：用合成用例加日常集打开每页，等 fonts.ready 后用 CDP 的 getPlatformFontsForNode 统计 isCustomFont=false 的字形数，除已声明没嵌入的符号字体外必须为 0。另一个脚本（probe_space.py）：把 font-family 里除别名外的字体换成 SimSun、Arial，单个 x 的文字外框位移必须 ≤0.1px。

- **默认的 paged 形式不等字体就显示页面：慢网下首屏先用观看者的系统字体画，0.2~2.7 秒后才换成嵌入字体**（影响 high，工作量 medium）
  - 证据：paged.ts 一开始就加载所有字体脚本，但 Player.show() 只等页面数据。字体脚本没到之前，别名这个 FontFace 根本没注册，浏览器没有阻塞期，直接用列表里下一个字体（'Microsoft YaHei' 等）。15 份真实课件用本地 HTTP 加 CDP 限速测：3G（1.6Mbps，RTT 150ms）下首页出现在 0.72~1.74 秒，字体全部到齐在 0.97~3.98 秒，中间空窗中位 0.95 秒、最长 2.74 秒，10/15 份课件首屏有系统字体字形（最多 133 个，去掉加载后仍用系统字体画的空格）；首屏和最终画面的 SSIM 最低 0.65（其中也有图片还没加载的因素）。4G（9Mbps）空窗 0.17~0.63 秒，中位 0.24 秒。对照 single 形式：FontFace 一开始就注册，首屏系统字体字形只有 0~1 个（空格）。直播课里学生中途进入、观看端用 sync 跳到别的页时，也都会看到这个先用系统字体再换字体的过程。
  - 建议：每页数据（或目录）带上这一页用到的字体别名。show() 显示前先 `await Promise.all(aliases.map(a => document.fonts.load(...)))` 并等对应字体脚本到达，设 2~3 秒上限，期间沿用现有的"加载中"提示，和等页面数据一样处理。预加载下一页时同时预加载它的字体。可以考虑把这一页的字体和页面数据一起拿到再显示；图片同样只预取了下一页，当前页图片也可以等 decode 完再显示（可选）。
  - 自动验收：tools/check-paged.py 加一项：用 CDP Network.emulateNetworkConditions 限到 3G，在第一个 .unppt-slide 插入时立刻统计 isCustomFont=false 的字形数，要求等于 0；同时记录"页面出现 → 字体齐"的空窗（scratch 里的 probe_fout.py）。

- **小于 1:1 显示时细线变淡（和 PowerPoint 规则相反）：真实课件 73% 的线 ≤1 幻灯片像素**（影响 medium，工作量 medium）
  - 证据：style/line.ts 把线宽取整到 1280 网格并至少 1px，SPEC 记的实测规则是 PowerPoint 不到 1 像素的线画成 1 个设备像素、颜色不变淡。真实课件里 1188 个有描边的元素中 869 个（73%）≤1 幻灯片像素。缩小显示时浏览器按面积抗锯齿：t-fonts-showcase 的边框在 1:1 及以上对比度是 55 级，1024x768 降到 31（56%），640x360 降到 20（36%），375x812@1 降到 13（24%），375x812@3 是 25（这里还叠加了半像素位移）。按 DOM 统计，常见的 800x450@1 嵌入框里 74% 的描边窄于 0.75 设备像素，375x812@2 是 73%，640x360@1 是 76%。和放大后的截图缩小相比 SSIM 不会掉（缩小同样会变淡），所以现有的比对指标也发现不了这个问题。
  - 建议：fit() 里设置 CSS 变量 `--unppt-px = 1/(s·dpr)`，即 1 个设备像素等于多少幻灯片像素。转码器给细线（取整前 ≤1px、实线）输出 `style="stroke-width:max(<w>px,var(--unppt-px,0px))"`。组合缩放里的线按组合比例近似即可。整页图（resvg）不认 CSS 变量，照旧画原线宽，不受影响。
  - 自动验收：在合成用例 lines-thin-dash 和带边框的表格上量线条对比度：640x360@1、800x450@1、375x812@2 下最暗列的对比度要 ≥ 1:1 时的 90%（scratch 里有量对比度的现成代码）。同时用 DOM 统计"线宽×s×dpr < 1 且没有用 max() 的描边占比"，要求为 0。

- **EMF/WMF 图片里的文字用观看者的系统字体：全量 13% 的课件可能受影响**（影响 medium，工作量 large）
  - 证据：EMF 转出的 SVG 作为 <image> 引用，图片里的 SVG 用不了页面注册的字体。产物里的 media/*.svg 没有任何 @font-face，<text> 写的是 '宋体'、'微软雅黑'、Arial 等名字，只能取观看者本机的字体：Windows 有，手机、Mac 没有，字形和字宽都不一样。抽样里合成用例有 126 个这样的 <text>，1 份真实课件有 1 个。全量扫描（只数 EMF 文字记录 EXTTEXTOUT 和 WMF 的 TEXTOUT / EXTTEXTOUT）：4887 份课件里 1723 份有 EMF/WMF，其中 638 份（13%）有带文字的图片，8373 个 EMF/WMF 文件里 1911 个带文字。这是上限，没有确认这些图片都在幻灯片上可见。SPEC D3 ⑨ 已经把它列为没做的部分。
  - 建议：二选一：(a) 有文字的 EMF 转出的 SVG 直接内联进页面 SVG（放进 <g>，加 clipPath），文字就能用页面的嵌入字体，字体选择走和正文、图表一样的逐字流程；(b) 每个 EMF SVG 自带 @font-face（data URL 的子集）。另外在 report.warnings 和字体检查里列出数量。
  - 自动验收：转码时统计 media/*.svg（和内联的 data:image/svg）里没有可用嵌入字体的 <text> 数量，写进 report 并设门禁（目标 0）。全量统计脚本见 scratch 里的 corpus_emf_text.py。

- **强制深色模式（Android WebView 算法变暗、浏览器自动深色）会改掉页面颜色**（影响 medium，工作量 small）
  - 证据：Chromium 打开 --blink-settings=forceDarkModeEnabled=true 时，6 页里 5 页不变（这个版本的强制深色没改 SVG 的填充色和文字颜色），1 页（4:3 课件，背景图片透明度 0.27）SSIM 只有 0.59。原因是透过半透明内容能看到 .unppt-stage 的 CSS 白底，它被变暗了。加 `<meta name=color-scheme content="only light">`、`dark`、`light dark` 或 CSS `color-scheme:only light`，结果都还是 0.5894，退出不了。在 SVG 里垫一个不透明白色 rect、并把舞台背景设成透明后升到 0.919，剩下的差别只在一个渐变填充的标题条里。
  - 建议：页面底色画在 SVG 里：根 SVG 第一个子元素放全尺寸白色 rect，或者转码器总是输出背景 rect。.unppt-stage 不再依赖 CSS 白底。color-scheme 声明可以顺手加上，但实测这个开关下它不起作用。
  - 自动验收：用 Chromium 加 --blink-settings=forceDarkModeEnabled=true 渲染全部合成用例，和正常模式比，每页 SSIM ≥ 0.99（scratch 里的 probe_dark.py、probe_dark3.py）。

- **手机竖屏看 16:9 课件：84% 的字小于 9 CSS 像素，而且禁止双指缩放**（影响 medium，工作量 small）
